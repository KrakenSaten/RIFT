## 1. Confirmed bugs, by severity

### Found on hardware, 2026-09-04

**H0. Every boot since 0.9.1 was a CLI rescue boot.** `TDeckSpeaker::begin` built
its `i2s_pin_config_t` with `= {}`, which left `mck_io_num` at 0 = GPIO0, not
`I2S_PIN_NO_CHANGE` (-1). The I2S master clock was routed to GPIO0, the trackball
click and boot strapping pin, and with the clock never stopped (48ad6dd9) the pin
read as held down from the first loop: a long press inside eight seconds of boot,
which is the rescue gesture. Mesh, screen and keyboard all work in that mode, so
nothing looked wrong; the USB companion protocol was dead and the click inert.
Measured: the "CLI Rescue" banner 3.8 s after every reboot with the port idle,
after a battery-only boot, and after a flash. Fixed and verified on the device
(DEVICE_QUERY answered, no banner). Not visible to the static review because the
driver reviewer had no IDF headers to check the sentinel against; the lesson for
the hardware session is that the SYSTEM screen should show the button's raw level
and whether the node is in rescue mode.

### High

**H1. Transport-coded packets feed a transport-code byte in as `path_len`.**
`MyMesh.cpp:361-368` hands `raw[1]` to `riftRxLog().add()` and `riftTropoStep()`.
`Packet::readFrom` (`src/Packet.cpp:65-74`) puts four transport bytes between the
header and `path_len` when the route type is `TRANSPORT_FLOOD` (0x00) or
`TRANSPORT_DIRECT` (0x03), so for those packets `raw[1]` is the low byte of
`transport_codes[0]`. Effect: RX-log rows show random hop counts for TF/TD packets,
and `riftTropoUsableHops` accepts any byte whose low six bits are 20..61 as a deep
packet — roughly two thirds of values — so five scoped-flood packets inside the
window raise a false "TROPO open" and a `notify()`. Scoped floods are what
`RiftScopes.h` exists to send, so this is reachable on RIFT's own mesh.
Fix: a pure `riftRawPathLenIndex(header)` in `RiftLogic.h` (5 for route 0/3, else
1), guarded on `len`, tested against all four route types.

**H2. A drag the screen did not consume is delivered as a tap on release.**
`UITask.cpp:7839` sets `_drag_moved` only when `handleDrag()` returned true. Every
cursor list returns false when the movement produced no step: SYSTEM `3028`/`3037`,
NODES `3766`, RADAR and the COMMS picker likewise. `UITask.cpp:7877` then treats the
release as a tap and `handleTouch()` activates whatever row is under the finger.
Scenario: SYSTEM page 1, cursor already on the last row, drag down and lift →
activates the row under the finger, which can be "Delete channel" or "Advert mesh".
The comment at SYSTEM `handleTouch` already names those two as rows that were hit
this way before. The August commit "The drag never suppressed its tap" fixed the
brace bug but not this.
Fix: decide "moved" in `UITask::loop` from the driver's own travel
(`rift_touch.dragTravel()` against a 4–6 px dead zone), independent of the screen's
return value; use the return value only for `refreshNow()`. Put the predicate in
`RiftLogic.h` with a test.

**H3. Migrated log entries are never evicted, and cap every live conversation at
two messages.** `riftLargestConv` (`RiftLogic.h:998-1011`) skips `RIFT_CONV_UNKNOWN`
keys as candidates and `riftConvSame(unknown, unknown)` is false, so unknown
entries are never a bucket. `riftEvictIndex` (`:1196`) evicts index 0 only while the
largest known conversation holds ≤1 entry; as soon as any conversation holds two,
it evicts from that one. With N unknown entries in the log (every v1/v2 record is
loaded as unknown, `UITask.cpp:495-524`), each live conversation is trimmed back to
two while the N dead entries stay forever and are re-saved on every flush. The test
`MigratedEntriesAreNotOneBucket` locks this in.
Fix: evict unknown entries first ("dead history first"), then fall through to the
largest-conversation rule. Update the test to drive 48 unknowns plus a stream of
messages and assert the live conversation grows.

**H4. Regions request only works for zero-hop repeaters.** `MyMesh.cpp:729` sends
`reply_path_len = 0`. The responder (`simple_repeater/MyMesh.cpp:147-160, 594-599`)
treats 0 as a valid direct path of length zero and answers with `sendDirect(...,
0)`, which is a zero-hop packet. For any repeater with a real route the request
arrives and the reply is lost; the panel reports a timeout. The comment at `:724`
("answer back the way the request came") describes behaviour the responder does
not have.
Fix: send `0xFF` (responder flood-replies) or the reversed `contact.out_path`.

**H5. `ADVERT_PATH_TABLE_SIZE` 16→96 is unconditional in `MyMesh.h:494`.**
It lands in every companion_radio build on every board: +9.4 KB `.bss`
(`sizeof(AdvertPath)` is 116), plus the 640-byte discovery table. That includes
STM32WLE5 targets with 64 KB SRAM (`variants/wio-e5-mini`, rak3x72). Nothing in
RIFT's CI matrix builds them.
Fix: `#ifndef ADVERT_PATH_TABLE_SIZE` default 16, set 96 from the RIFT env; wrap the
discovery table in `#ifdef RIFT_VERSION`.

### Medium

**M1. RADAR can stall silently in `BLE_RUNNING`.** `scan->start()` at
`UITask.cpp:4188` returns `bool` and is ignored; the only exit from that state is
the completion callback. If start fails (e.g. a stop still in flight from the `S`
handler or a STOPPING re-entry) no more Wi-Fi sweeps, no age-out, no watch checks,
until the user leaves the screen. Fix: check the return, and add a deadline in
`BLE_RUNNING` (dwell + 1 s) that stops and moves on, logged.

**M2. The 90 s watch "gone" window is dead code.** `rfAgeOut` (`:3960`) drops
entries older than 45 s and runs before `rfWatchCheck`, whose 90 s compare at
`:4045` can therefore never see an entry aged 45–90 s. A device quiet for 60 s is
reported gone and then re-alerted. Fix: keep watched keys until
`RIFT_WATCH_GONE_MILLIS` in `rfAgeOut`, or track `last_seen` on the watch itself.

**M3. Full RF table refuses a watched device that is not yet in it.** The guard at
`:3921` protects watched entries already present; a watched device arriving weaker
than every non-watched entry is dropped before insertion, so the watch says
"not heard" while the radio hears it — the exact failure the comment above it says
the code prevents. Fix: look the key up in the watch list before the RSSI test and
take `weakest` unconditionally if watched.

**M4. Channel sender is split on CP437-translated text.** COMMS calls
`senderSplit()` (`:6289`) on the output of `riftTranslateUTF8` (`:6021`, `:6068`).
`riftChannelSenderNth` rejects bytes < 32, and the translator emits 0x01/0x02 for
ø/Ø and 0x03–0x1B for mapped emoji, so "Bjørn: hei" fails the split: no sender
colour, no name lift, and the contact-disambiguation `strcmp` against UTF-8
`contact.name` can never match a Nordic name. Fix: split on the raw `p->msg`, then
translate sender and body separately. Store the split offset in the log entry at
`add()` time to also remove the per-frame `searchContactsByPrefix` cost.

**M5. Wake tap swallowed on COMMS while the display is off.** The drag branch
(`:7825-7850`) has no `isOn()` guard and COMMS history returns true for any `dy`,
so a wake touch with ≥1 px of jitter sets `_drag_moved`, the release is suppressed,
and the screen stays dark (and scrolls invisibly). Fix: skip the drag branch when
the display is off; treat the release as a wake.

**M6. `riftTranslateUTF8` deletes whitespace controls.** `RiftLogic.h:620` drops
every cp < 32, so a message with a newline or tab renders the words merged. Fix:
map 0x09/0x0A/0x0D to a space (collapse CR LF); test `"a\nb"` → `"a b"`.

**M7. Touch calibration is not applied.** `TDeckTouch.cpp:63-64` does only the
axis swap and invert. With HANDOFF's measured corners, raw (228,8) maps to (8,11)
and raw (6,310) to (310,233), not (0,0) and (319,239): up to 11 px short at the
corners, which is enough for a tap on the top rows of the nav bar to miss the
`ty >= height-16` test. Fix: scale and offset from the four raw endpoints
(`x = (raw_y-8)*319/302`, `y = (228-raw_x)*239/222`, clamped), with the endpoints
as `TOUCH_CAL_*` build flags. Caveat: only if the finger really reached the corner
pixels when those raws were measured; put the raw and mapped values side by side on
SYSTEM and re-measure once.

**M8. Every screen wake re-initialises the panel.** `turnOn()`
(`ST7789NativeDisplay.cpp:67`) calls `begin()`, which runs `display.init()`: about
200 ms of `delay()` (SWRESET 150 ms plus five 10 ms steps) with no loop watchdog,
so 200 ms of LoRa blindness per wake, and the backlight is driven high before the
reset so the old frame flashes. `turnOff()` never sleeps the panel, so the reset is
unnecessary. Fix: sleep in `turnOff()`, wake with `enableSleep(false)` on a
non-blocking deadline, re-blit the canvas, then backlight on.

**M9. Backing out of channel-key entry loses the channel name.** CH_NAME → ENTER
copies `_edit.buf` into `_ch_name`; choosing "paste a key" re-`begin()`s the editor;
BACK from CH_KEY_ENTRY (`UITask.cpp:3108`) then BACK from CH_KEY_CHOICE (`:3101`)
returns to CH_NAME with an empty field. Fix: at `:3101` re-seed the editor from
`_ch_name`.

**M10. Deleting a channel never clears its scope entry.** `:3225-3252` purges the
conversation and unread state but not `riftScopes()`. Dead entries persist in RAM
and `/rift.cfg`; at eight of them a fresh channel gets "No scope slots left" while
zero scopes are live. Fix: `riftScopes().clear(idx)` and save on success.

**M11. `removeChannel()` leaves a live listener on the all-zero key.**
`MyMesh.cpp:841` blanks the slot with `setChannel(idx, blank)`, and
`BaseChatMesh::setChannel` derives `hash = sha256(16 zero bytes)` unconditionally,
so the slot now matches anyone transmitting on the zero key and delivers with an
empty channel name. Inherited from upstream's `CMD_SET_CHANNEL` delete path, but
RIFT is the first on-device deleter. Fix: drop messages whose slot name is empty in
`onChannelMessageRecv`, or add a `clearChannel()` upstream.

**M12. `rift-release.yml` deploys the flasher on every manual run.**
The gh-pages step (`:207-212`) is unconditional and `peaceiris/actions-gh-pages`
replaces the branch, so one "Run workflow" click from any branch replaces the
released `rift-merged.bin` at krakensaten.github.io/RIFT with a `dev-<sha>` build.
The three earliest gh-pages deploys point at untagged commits, so it has happened.
README says the page is published "on every v* tag ... so it cannot drift", which
is false. Fix: `if: github.ref_type == 'tag'` on that step, or publish dispatch
builds under `destination_dir: dev/`.

## 2. Plausible, not confirmed

- **Free-running I2S ring.** With the engine never stopped, `i2s_write(…, 0)` can
  hand the DMA a descriptor it is still clocking out; start latency then varies
  0–290 ms and `_audio_started_at` is set early, which skews `isDraining()` and the
  silence measurements. Measure: time from first write to queue-empty on SYSTEM; a
  spread of 0–300 ms confirms. Candidate fix: `i2s_stop / zero / i2s_start` right
  before a tone (microseconds of BCLK gap, far below the amp's clock-loss timeout).
- **Touch has no failure backoff or re-probe** (keyboard has both). A NACK at boot
  means dead touch until reboot; a degraded bus means 1–3 blocking transactions
  every 8 ms. Also accepts 0xFF garbage frames as a touch at (65535, −65296),
  which is the "max step far above the rest" case the drag log was written for.
  Measure: `micros()` around `rift_touch.poll()` on SYSTEM; reject `points > 5` and
  out-of-range raws and count them.
- **Trackball pulses lost during the ~40 ms frame blit** (edge detection needs two
  consecutive samples). Measure with a pin-change ISR counter next to the polled
  count.
- **`WiFi.mode()` / `BLEDevice::init` block for tens to hundreds of ms** on RADAR
  entry and exit, and with `WiFi.persistent(true)` the mode change is written to
  NVS. Set `persistent(false)`; time the calls.
- **Loop-task stack:** `RfContact snap[48]` (~2.1 KB) on the stack per RADAR frame
  with the default 8 KB loop stack. Read `uxTaskGetStackHighWaterMark(NULL)` on
  SYSTEM.
- **`riftMatchResponse` LOGIN consumes any response from that key prefix**, so a
  companion's pending status reply from the same repeater reports `onLogin(false)`.
- **ACK table stores `ContactInfo*`**, which dangles after `removeContact` shifts
  the array (inherited); store a 6-byte prefix and re-look-up.
- **`findFreeChannelSlot` can return 0** after a companion app clears Public, and
  `removeChannel` then refuses the slot as "Public".
- **`installChannel` has no duplicate check.**
- **The I²C diagnosis may be inverted:** upstream ran `rtc_clock.begin(Wire)`
  before `Wire.begin()`, where a transaction fails without touching the bus, so the
  RTC probes never ran on stock; the fork moved `Wire.begin` first, made the probes
  real, and then observed the 920 ms state. ARCHITECTURE's "all four stock
  environments have the same bug" is therefore unproven. Net effect is benign.
- `rift-flash.py` prints "verified" before `settle_boot_slot`; with
  `--keep-otadata` the device may still boot app1 after a green verify.
- `audit-cmd-guards.py` counts a same-line gate as covering a read that precedes
  it; `CMD_SEND_PATH_DISCOVERY_REQ` (52) reads byte 1 before the length test and is
  not in the limits table (harmless only because the frame tail is zeroed).
- `riftConvSame` for two channel keys with fingerprint 0: the comment says must not
  match, the test asserts they do. Pick one.

## 3. Tests

The suite is well-motivated but stops at the `RiftLogic.h` boundary. Zero coverage
for the four stateful headers, all of which compile against `test/mocks` today:

- `RiftRepeaterSession` — `pushLine` UTF-8 cut at 63, ring order, `onCliReply`
  multi-line split, secret window blocking a later reply, login timeout,
  `onRegions("a,,b")`.
- `RiftScopeTable` — replace-not-append, compaction on `clear`, fp-0 refusals,
  full table.
- `RiftRxLog` — clamping, `peek` order after wrap, tx/rx split.
- `RiftEventLog` — truncation at 63, `dropped` accounting.
- Log-record encode/decode (`RiftMsgLog::saveInner` / `load`, three file
  versions) — extract to pure functions and round-trip v1/v2/v3 fixtures. This is
  the file the project says it cannot afford to corrupt.
- Boundary cases: tropo hops 19/20 and 61/62; `riftDecodeRepeaterStats` lengths
  45–47 and 49–55; UTF-8 decoder on `"\xC3"`, `"\xE2\x9D\x41"`, `"\xF0\x9F\x99\x41"`;
  `riftChannelSender` at 31/32 bytes.

Tautological or weak tests to replace: `CanDirectMessage.OneAnswerForEveryType`
(compares `f(t)` with `f(t)`), `HopBucket.DoesNotAdaptToTheNetwork`,
`ScreenTransition.RaisingAPopupLeavesNothing` and its twin,
`Tropo.OpensOnceAfterEnoughDeepPackets` (checks only the last return),
`FormatDuration.ASevenCharacterResultFitsTheStatedMinimum`.

Add a `riftRawPathLenIndex` test (H1), a drag-dead-zone test (H2), and an
eviction-sequence test (H3) as the first three.

## 4. Structure and maintainability

- **`UITask.cpp` is 7,500 lines.** Split by screen: `RiftSystemScreen.cpp`,
  `RiftRadar.{h,cpp}` (table, watches, waterfall, state machine — ~450 lines that
  the `RIFT_RADAR` guard could then wrap once), `RiftCommsScreen.cpp`,
  `RiftNodesScreen.cpp`, `RiftRepeaterScreen.cpp`, with `UITask.cpp` keeping the
  loop, navigation and overlays. `platformio.ini` already globs
  `ui-rift/*.cpp`.
- **`RiftLogic.h` is 1,835 lines** with banner-delimited sections and few
  cross-dependencies: `RiftUtf8.h`, `RiftTime.h`, `RiftConv.h`, `RiftCli.h`,
  `RiftTropo.h`, `RiftPacketNames.h`. Two sections are physically misplaced
  (channel colours between `riftUtf8Decode`'s comment and its definition; the
  eviction comment 100 lines above `riftEvictIndex`).
- **Centralise the drag/tap decision** (H2) and **the UTF-8 translate-before-draw
  step** (M4, L7): a `riftDrawUTF8(display, x, y, text)` wrapper removes ~10
  hand-rolled `char tmp[]; riftTranslateUTF8(...)` sites.
- **SYSTEM's five text-edit modes** are copy-pasted state handlers; M9 and L1 are
  both divergences in that copy. A `{commit, back_mode}` table, or a
  `RiftSystemFsm` step function in `RiftLogic.h` with tests like
  `riftScreenTransition`, closes the class.
- **Persistence:** `saveInner`/`load` and `riftSaveSettings`/`riftLoadSettings`
  hand-roll the same length-prefixed record I/O. A small `RiftFileWriter/Reader`
  with a sticky `ok` flag removes ~40 lines and makes "writer and reader disagree by
  one byte" impossible.
- **`sprintf` into fixed buffers** is used in ~25 places alongside `snprintf` in
  others. All are bounded today; a longer `RIFT_VERSION` or `RIFT_MARK` name is the
  overflow. Adopt `snprintf` uniformly.
- Dead members: `_msgcount` (never written), `_companion_backlog` (never read),
  `RIFT_WF_SLICES` 40 vs 30 rows used, `next_led_change` as `int` holding millis.

- `upstream/main` (meshcore-dev/MeshCore) is **49 commits ahead** of the fork
  point (`727fc051`, 2026-08-09); upstream is at `v1.17.1`, RIFT builds on
  `v1.17.0`. The only files both sides changed are `MyMesh.cpp` and `MyMesh.h`.

  upstream lines that are legitimately upstream bug fixes (command-frame guards,

  rather than conflicting on it. The RIFT-only members (`resolvePathHash`,

  defined in `ui-rift/MyMeshRift.cpp` with declarations under `#ifdef
  RIFT_VERSION`, and the `riftLogf` sprinkles collapse into one `AbstractUITask`
  hook. That cuts the next merge's conflict surface by roughly two thirds.
- `main.cpp`: collapse the nine `RIFT_MARK` lines and the SPIFFS block into a
  `riftPreMount()/riftMountFs()` pair.
- HANDOFF's open item 0 (ask upstream what `TODO - deprecate the 'Connections'
  stuff` means) was queued 2026-08-23 and has no follow-up. It still blocks room
  servers.
