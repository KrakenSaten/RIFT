Radio Intelligence · Field Terminal

Firmware for the original LilyGO T-Deck that turns it into a standalone MeshCore terminal — read and write mesh messages on the keyboard it already has, with no phone and no companion app. Version (loading).

This browser cannot flash an ESP device. Use Chrome or Edge on a desktop or laptop, or take the command-line route below. Firefox and Safari do not implement WebSerial, and no browser on a phone or tablet does. Flashing needs this page over https and permission to open a serial port. If you are on https and still see this, the port was refused or is already open in another program - close any serial monitor and reload.

Requires Chrome or Edge on desktop. Firefox and Safari have no WebSerial — use the command-line route below.

The first boot can take one to two minutes. If the boot screen reads Formatting SPIFFS, the filesystem is being created and the device is working — it just cannot show progress, because the format blocks everything else while it runs. Leave it alone and wait it out. We assumed the device was dead the first time we saw it.

What you get

  • A terminal, not a notifier. Upstream's on-device UI shows an unread count and previews messages but cannot compose. RIFT types, sends, and shows delivery state — ACK 1.2s when it landed, no ack when it did not, and nothing at all on channel messages, where no acknowledgement exists to report.
  • æ ø å — typed, not just read. The T-Deck keyboard is a US QWERTY with no Nordic keys. Double-tap a vowel and pick the form: a offers æ å ä, o offers ø ö, uppercase too. Norwegian, Swedish and Danish. Reading works as well — incoming UTF-8 is mapped to the panel's font, and ø, which the font does not contain at all, is drawn stroke by stroke.
  • Passive Wi-Fi and BLE radar, with a proximity watch. Device counts, signal bands and a waterfall of observed 802.11 activity. Mark a device and the screen tells you when it turns up again. Strictly passive — nothing is transmitted, nothing is probed. It is not a spectrum analyser either: the ESP32 gives no access to raw RF, so what you see is observed traffic.
  • Find out who can hear you. One button asks every repeater in direct range to answer, and each reply carries two signal readings: how well you heard them, and how well they heard you. Nothing else in the firmware can tell you the second one, and asymmetric links are common. Direct neighbours only — it does not search the wider mesh.
  • Is the mesh alive around me. The home screen answers that and nothing else, from actual radio receptions rather than from whether a phone is plugged in: how long since anything was heard, and how much. A node sitting in a busy mesh with no companion app is not "standby".
  • Message history survives a reboot. MeshCore keeps no messages of its own. RIFT writes its log to flash, and deliberately does not claim to know the fate of a message that was still awaiting acknowledgement when the power went.
  • Readable outdoors, in daylight or dark. Night and day palettes with the same geometry. Nothing encodes data in brightness where a shape can carry it, because reflected sunlight collapses a grey ramp — so freshness is a filled marker versus a hollow one. Channels get colours picked by sweeping every value the panel can produce for the ones that stay legible on both black and white.
  • A console, not a black box. SYSTEM carries an event log and live diagnostics: which keys the hardware reports, the I²C bus, boot timings phase by phase, free heap, the reason for the last reset. Most of it exists because a bug was easier to see than to reason about.

Built on MeshCore, which is the hard part. Multi-hop routing, the packet protocol, encryption, acknowledgements, path discovery, the SX1262 driver and support for dozens of boards are all MeshCore, by Scott Powell and well over a hundred contributors. RIFT changes none of it and uses it unmodified. What this fork adds is a T-Deck user interface and its input drivers.

The RIFT code was written by an AI assistant (Claude), directed and supervised by mstr, who specified the work, tested every change on hardware and is accountable for what ships here. That supervision is not a formality — the AI cannot flash a board or watch a radio, so nothing was accepted because it compiled. Several things it got wrong were caught exactly there: a USB API that only reports true once a host opens the port, a touch controller parsed by the datasheet's byte order instead of the one the hardware returns, and a whole feature built on a code comment claiming the keyboard repeats a held key, which it does not. MeshCore itself is not AI-written.

Erase, or keep your identity?

The installer asks this before it writes anything. It matters more here than on most devices, so it is worth understanding before you click.

Answer "no" to erasing if this device is already a node you use. MeshCore keeps its private key in a file on the SPIFFS partition at 0xc90000. Erasing wipes it, and RIFT deliberately disables MeshCore's private-key export command — so there is no way to back the key up beforehand and no way to recover it after. The device returns as a brand new node and your contacts will not recognise it. Erasing also costs one to two minutes on the next boot while the filesystem is rebuilt.

Keeping your data is safe: the firmware image spans offset 0 to roughly 0x19d000 — bootloader, partition table, boot selector and application — and SPIFFS sits well past the end of it. Your key, contacts and channels are not in the way of the write.

Erase deliberately when you are setting up a device for the first time, moving it to a new identity, or recovering from a filesystem you believe is corrupt.

One thing happens either way: NVS is erased (0x9000 falls inside the image and is filled with 0xFF), which holds Arduino-side preferences rather than MeshCore state.

If the browser cannot see the device

The T-Deck's ESP32-S3 uses native USB, which re-enumerates as the firmware boots. If no port appears, or the connection drops mid-flash, hold the BOOT button while plugging the cable in to force the bootloader, then try again.

Command-line route

Download *-merged.bin from the releases page and write it with esptool. Adjust the port.

python -m esptool --chip esp32s3 --port COM5 write-flash 0x0 rift-merged.bin

To upgrade only the application and leave the bootloader and partition table alone, use the plain .bin at the application offset instead:

python -m esptool --chip esp32s3 --port COM5 write-flash 0x10000 rift.bin

Those are esptool 5 command names. Esptool 4 — which is what PlatformIO bundles — spells them with underscores: write_flash. Invoking through python -m esptool rather than a bare esptool works on both, since the two versions install different console scripts.

If esptool reports that the port does not exist while it is clearly listed, something else still has it open. Including this page: WebSerial holds the port until the tab is closed, so flashing here and then reaching for esptool fails until you close the tab. A serial monitor does the same.

Building it yourself
