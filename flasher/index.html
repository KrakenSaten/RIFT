RIFT

Radio Intelligence & Field Terminal — firmware for the original LilyGO T-Deck. Version (loading).

Requires Chrome or Edge on desktop. Firefox and Safari have no WebSerial — use the command-line route below.

The first boot can take one to two minutes. If the boot screen reads Formatting SPIFFS, the filesystem is being created and the device is working — it just cannot show progress, because the format blocks everything else while it runs. Leave it alone and wait it out. We assumed the device was dead the first time we saw it.

What this does to the device

The installer writes a merged image at offset 0: bootloader, partition table, boot selector and application. Concretely:

  • Your node identity survives. MeshCore keeps the private key in a file on the SPIFFS partition, which sits at 0xc90000 — far past the end of this image. Upgrading in place keeps your key, your contacts and your channels.
  • NVS is erased (0x9000 falls inside the image and is filled with 0xFF). That holds Arduino-side preferences, not the MeshCore identity.
  • Message history is lost on every reboot regardless — RIFT's log is RAM-only by design.
Do not use a full chip erase unless you mean it. Erasing wipes SPIFFS and therefore the private key. RIFT deliberately disables MeshCore's private-key export command, so there is no way to back the key up first and no way to recover it afterwards. The device comes back as a new node with a new identity, and your contacts will not recognise it.

If the browser cannot see the device

The T-Deck's ESP32-S3 uses native USB, which re-enumerates as the firmware boots. If no port appears, or the connection drops mid-flash, hold the BOOT button while plugging the cable in to force the bootloader, then try again.

Command-line route

Download *-merged.bin from the releases page and write it with esptool. Adjust the port.

python -m esptool --chip esp32s3 --port COM5 write-flash 0x0 rift-merged.bin

To upgrade only the application and leave the bootloader and partition table alone, use the plain .bin at the application offset instead:

python -m esptool --chip esp32s3 --port COM5 write-flash 0x10000 rift.bin

Those are esptool 5 command names. Esptool 4 — which is what PlatformIO bundles — spells them with underscores: write_flash. Invoking through python -m esptool rather than a bare esptool works on both, since the two versions install different console scripts.

If esptool reports that the port does not exist while it is clearly listed, a serial monitor still has it open. Close it and retry.

Building it yourself

Everything here is produced from source by CI; the repository README has the two environment gotchas that cost real time, and the full build instructions.

RIFT is an independent fork of MeshCore by Scott Powell and contributors, MIT licensed. The mesh stack, LoRa drivers and protocol are theirs; RIFT adds a keyboard-driven terminal UI on top. The install button is ESP Web Tools, loaded from unpkg.
