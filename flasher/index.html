RIFT

Radio Intelligence & Field Terminal — firmware for the original LilyGO T-Deck. Version (loading).

Requires Chrome or Edge on desktop. Firefox and Safari have no WebSerial — use the command-line route below.

The first boot can take one to two minutes. If the boot screen reads Formatting SPIFFS, the filesystem is being created and the device is working — it just cannot show progress, because the format blocks everything else while it runs. Leave it alone and wait it out. We assumed the device was dead the first time we saw it.

Erase, or keep your identity?

The installer asks this before it writes anything. It matters more here than on most devices, so it is worth understanding before you click.

Answer "no" to erasing if this device is already a node you use. MeshCore keeps its private key in a file on the SPIFFS partition at 0xc90000. Erasing wipes it, and RIFT deliberately disables MeshCore's private-key export command — so there is no way to back the key up beforehand and no way to recover it after. The device returns as a brand new node and your contacts will not recognise it. Erasing also costs one to two minutes on the next boot while the filesystem is rebuilt.

Keeping your data is safe: the firmware image spans offset 0 to roughly 0x19d000 — bootloader, partition table, boot selector and application — and SPIFFS sits well past the end of it. Your key, contacts and channels are not in the way of the write.

Erase deliberately when you are setting up a device for the first time, moving it to a new identity, or recovering from a filesystem you believe is corrupt.

Two things happen either way: NVS is erased (0x9000 falls inside the image and is filled with 0xFF), which holds Arduino-side preferences rather than MeshCore state; and message history is lost, which happens on every reboot regardless because RIFT's log is RAM-only by design.

If the browser cannot see the device

The T-Deck's ESP32-S3 uses native USB, which re-enumerates as the firmware boots. If no port appears, or the connection drops mid-flash, hold the BOOT button while plugging the cable in to force the bootloader, then try again.

Command-line route

Download *-merged.bin from the releases page and write it with esptool. Adjust the port.

python -m esptool --chip esp32s3 --port COM5 write-flash 0x0 rift-merged.bin

To upgrade only the application and leave the bootloader and partition table alone, use the plain .bin at the application offset instead:

python -m esptool --chip esp32s3 --port COM5 write-flash 0x10000 rift.bin

Those are esptool 5 command names. Esptool 4 — which is what PlatformIO bundles — spells them with underscores: write_flash. Invoking through python -m esptool rather than a bare esptool works on both, since the two versions install different console scripts.

If esptool reports that the port does not exist while it is clearly listed, something else still has it open. Including this page: WebSerial holds the port until the tab is closed, so flashing here and then reaching for esptool fails until you close the tab. A serial monitor does the same.

Building it yourself

Everything here is produced from source by CI; the repository README has the two environment gotchas that cost real time, and the full build instructions.

RIFT is an independent fork of MeshCore by Scott Powell and contributors, MIT licensed. The mesh stack, LoRa drivers and protocol are theirs; RIFT adds a keyboard-driven terminal UI on top. The install button is ESP Web Tools 10.4.0, loaded from unpkg.
